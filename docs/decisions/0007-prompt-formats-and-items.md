# 0007: Prompt formats and "items"

**Status:** accepted 2026-09-17 (owner request: more transparency and customizability in how tasks become prompts, and support for inputs that are not texts to classify, such as questionnaire items)

## Decisions

1. **Templates with placeholders** (owner's choice), inspired by `rollama::make_query()`:
   - **Where it lives:** a task has a `prompt` section with `system` (null for no system message), `user`, `scale`, `code`, `code_separator` and `answer_instruction`.
   - **Placeholders:**
     - in `system` and `user`: `{instructions}`, `{scale}` and `{answer_instruction}`; `{item}` only in `user`, exactly once;
     - in `scale`: `{codes}`;
     - in `code`: `{response}` (required), `{label}`, `{value}` (only with values) and `{id}`.
   - **Syntax:** `{{` and `}}` produce literal braces. Substitution is single-pass, so braces inside instructions, labels or items are never expanded.
   - **Message order** is fixed: an optional system message, one user/assistant pair per example (the example rendered through `user`, followed by its response code), then the scored item through `user`.
   - **The answer is still read at the start of the assistant turn.** There is no answer prefill; plan section 6's rule against undocumented prefill is unchanged.
2. **Defaults reproduce renderer version 1 exactly.**
   - All 478 prompts in the fidelity fixtures, rebuilt with the new renderer and tokenized by the official Hugging Face tokenizer, equal the recorded reference tokens. The fidelity evidence therefore still applies.
   - The renderer version is now 2, so the engine fingerprint changes, and prepared tasks from renderer 1 must be prepared again.
3. **Errors vs warnings.**
   - **Errors (`invalid_task`):** structural problems — `{item}` missing or repeated, `{item}` in `system`, an unknown placeholder, an unmatched brace, `{codes}` not exactly once, `{response}` missing, `{value}` without values.
   - **Warnings (prepare diagnostics), for probably unintended formats:** `unused_instructions`, `empty_instructions`, `unused_answer_instruction`, `scale_not_in_prompt`.
   - `instructions` may now be empty.
   - A substring check for response codes appearing in the prompt was rejected: single letters such as `A` always occur in ordinary words, so the check was meaningless.
4. **"Items" instead of "texts"** (owner's choice) in the user-facing API:
   - `score_items(items, ids, task, engine, ...)` in R, `engine.score(items, ...)` in Python, and the `{item}` placeholder;
   - examples use an `item` column (R) or field (Python and task JSON);
   - `prepare_task(..., preview_item =)`, `preview_prompt(prepared, "item")`;
   - item failure messages ("item is missing" and so on).

   The wire format keeps `{"id", "text"}` for request items, `preview_text`, and `text_sha256` in result and checkpoint files, where "text" means the item's text. The package is unreleased, so the old names were removed rather than deprecated.
5. **Offline message previews** (owner's choice):
   - `task_messages(task, item)` in R and `ScoringTask.messages(item)` in Python build the messages locally, with the same rules and the same number formatting (canonical JSON numbers) as the service.
   - `tests/fixtures/prompts/messages.json` (10 tasks × 4 items, generated by the service) keeps the three implementations identical.
   - The prepare response's previews now include `messages` alongside the exact chat-template `prompt`.
6. **Number formatting in R:** R's own number parser isn't correctly rounded at extreme exponents, so the shortest round-trip digits are found with jsonlite's parser (C `strtod`). All 2,998 doubles formatted by Node.js match.
7. **Documentation:**
   - `docs/prompts.md` shows the full default prompt, the exact rendered text for the supported model, every template part and placeholder, common changes (instructions after the item, scale layouts, answer instruction, questionnaire items), warnings, and what LLikert never adds.
   - `?scoring_task` and `?prompt_format` describe how the prompt is built.

## Evidence (2026-09-17)

- **Python:** 232 tests pass. They include 21 service prompt tests, and client offline messages matching all 40 fixture cases.
- **R:** `devtools::test()` passes all files, including 104 prompt checks (messages fixture parity and the 2,998-number formatting fixture).
- **Small-model integration and stress tests:** 10 passed.
- **Default prompts vs fidelity fixtures:** 478 of 478 token-identical under the official tokenizer.
- **Not executed:** the F32 fidelity gate on the GPU and the container acceptance test. The owner's own `llikert` container occupied the GPU and port. Both should be rerun before release; the token identity above means no change in probabilities is expected.
